# Theme Park project rules

- Starter SNES v10 is the only workflow authority.
- Execute canonical owners 01C through 18C in order; do not move unfinished work forward.
- The canonical ROM stays outside this project and is passed to read-only tools by absolute path.
- Rock n Roll Racing may be inspected only after a version is complete, and only for workflow questions. Never copy or adapt its code, data, hashes, generated output, tests, or results.
- Emulator/oracle use is forbidden until the static core is complete. It may then confirm missing or broken behavior, never author semantics, contexts, targets, or lowering.
- Per the user's later instructions, the completed source-derived core is connected to the requested Starter v11 frontend and qualified before compaction. Optional frontend refinements follow compaction and comparison with the six reference projects.
- Core construction builds produce objects and static libraries. For 17C/18C,
  a Theme Park-only natural-validation runner may be created and executed inside
  this project's Temp workspace to collect master-clock framebuffer/PCM evidence.
  It must link only the current Theme Park core, must not become source authority,
  and must not use an emulator/oracle or copied recomp-project code.
- Unknown mappings, contexts, targets, epochs, devices, values, or semantics fail closed.
- For 03C-07C S-CPU work, use a bounded repeated loop: discover a complete source/proof family; understand its exact E/M/X, producers, successors, returns, and subsystem effects; admit only proved contexts; lower that family into current static authority; reconcile discovered/admitted/generated/linked sets; then repeat. Never accumulate unexplained staged contexts or bulk-lower candidates.
- TP07F486 is the last per-family whole-surface cold-verification baseline. From TP07F487 onward, do not rerun semantic checks over already proved unchanged contexts: freeze their generated-body and hardware-event hashes, prove each later tranche is append-only, and verify only new contexts plus the explicit impact set of any changed shared owner. Batch repeat-only dependency-eligible families. Cheap global membership, dispatcher, purity, hardware-count and no-compilation invariants still run for every tranche. Run the next full semantic cold pass only if a global mechanism changes, an old body/event mutation is detected, or the complete final 07C surface is being closed. Rechecking unchanged proved bodies after every family is prohibited testing-for-testing's-sake.
- The 07C hardware checklist must distinguish exact proved effective-address events, conservative address-class intersections, and unresolved producer obligations. Indexed, direct-page, indirect, stack-relative, and block-move forms may not disappear merely because their literal operand is outside an MMIO range. Keep unresolved facts offline, deduplicate/group them with member hashes, never promote them to reached hardware without a finite address proof, and cold-regenerate the complete checklist at final 07C closure.
- Before 03C-07C, inspect Starter v10 context-discovery/lowering guidance and six existing SNES static recomp projects locally and on the owner's Junior Jones GitHub for methods only. Do not copy any project-specific source, ROM data, addresses, generated bodies, hashes, or results.
- After 07C is completely reconciled and independently confirmed, stop before 08C. At that gate, create Starter SNES v12 under the external `files` folder by reworking v10 versions 02-07 from the recorded Theme Park and six-project method lessons. Do not create the v12 folder early. For each version, preserve its responsibility while documenting original requirement, observed weakness, Theme Park deviation/repair, reusable improvement, start-to-finish checklist, required evidence, failure/reopen rules, and handoff gate. Never import project-specific code, ROM facts, addresses, hashes, counts, or acceptance claims into v12.
