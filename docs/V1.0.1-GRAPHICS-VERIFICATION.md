# Version 1.0.1 graphics verification

Date: 18 November 2026. Status: locally built and headless tested.

The 1.0.0 renderer contained demonstrated errors in OBJ word/byte addressing,
background scanline origin, mosaic origin, BG/OBJ priority and Mode 2 offset-map
column selection. An overflow exit also failed to mark its prepared OBJ line
cache complete. Version 1.0.1 corrects these six bounded issues. Native generated
S-CPU/S-SMP authority, ROM identity and the production source inventory are
retained. Mesen is an independent confirmation tool, never production authority.

## Verification

- MSVC Windows x64 production core and Launcher build successfully. The executable
  reports 1.0.1 and depends on Windows system DLLs; SDL and the CRT are static.
- A read-only native observer linked to the package's actual core library executes
  the complete 11,100-frame construction/pricing route. All per-frame recorded
  fields match the qualified final renderer candidate across all 11,100 frames.
- The initial park matches the pinned Starter SNES v12 headless Mesen reference
  exactly at all 57,344 visible pixels. The 1.0.0 source differed at 30,400 pixels.
- All 2,000 boot frames match the oracle at the same frame or the documented next
  frame: 1,955 exact, 45 at oracle N+1. All 130 enabled mosaic frames have a match.
- Independent actual-renderer fixtures cover 32 BG/OBJ priority combinations,
  122,883 Mode 2 offset cases and 43,008 mosaic/vertical-origin cases. Dedicated
  cases cover OBJ base/name addressing and the overflow-line cache exit.
- Ordinary controller inputs open the park without RAM writes. Separate source
  and oracle runs execute 12,000 frames; the read-only park-open flag stays set.
- Temporal analysis of 57,300 selected run frames finds no one-frame whole-image
  A-B-A event. The 2,655 saved consecutive image triples show no one-frame local
  transient. This is scoped observation, not proof of universal absence of flicker.
- Construction menu blackouts coincide with intentional brightness fades and
  forced blank. Idle/open-park routes have no post-entry full blackouts.

## Interpretation and limits

The oracle has seven leading and eight trailing black rows around its 224-line
picture. Comparison removes those rows and records controller-poll/frame phase.
Postboot inputs require a calibrated one-frame oracle adjustment; original and
adjusted runs are retained. Later path/camera state can diverge between runs, so
those different-VRAM screenshots are not classified as renderer pixel errors.

The player report said only "Graphic issues." The demonstrated corrections do
not prove it described these exact faults. Headless work does not qualify GPU
presentation, monitor/vsync behavior, window resizing, physical controller use,
another PC, every country/ride, dense visitor parks or ride boarding. Known audio
limitations remain. Generic active-display mosaic reanchoring and full STAT77
flag behavior remain outside this correction; the recorded mosaic writes are
VBlank configuration or startup writes under forced blank.

The full report, source-bound run receipts, raw screenshots/RAM dumps, temporal
logs, pinned Mesen profiles and reproducible diagnostics are retained in the
development graphics-audit-20261118 lab. Gameplay probes and ROM data are not
included in this portable source or Windows package. Publication and remote CI status are recorded on the repository release and
Actions pages; this document records the local headless graphics qualification.
